# دليل تنسيق README للمشاريع

هذا الدليل هو القاعدة الموحدة لعرض المشاريع على GitHub بأسلوب بسيط ومرتب واحترافي. يُطبّق على ملف `README.md` لكل مشروع، مع تكييف النصوص والتقنيات والصور حسب المشروع نفسه.

## 1. المبادئ الأساسية

- الغرض من README هو **تعريف الزائر بالمشروع وكيف يعمل**، وليس تسجيل أعمال الصيانة أو تاريخ المستودع.
- كتابة جمل قصيرة وواضحة. الوصف يعكس **وظائف حقيقية موجودة في الكود**؛ لا تُضاف مزايا أو تقنيات لمجرد تحسين المظهر.
- المحافظة على التنسيق البصري الموحد: عنوان وشعار في المنتصف، شارات تقنية محدودة، صور منظمة، فواصل بين الأقسام، وعناوين بالإنجليزية مع العربية.
- استخدام الصور الحقيقية غير المقصوصة أو المشوّهة. عند عدم توفرها، يُترك سطر بسيط في قسم الصور حتى تُضاف لاحقًا، دون صور وهمية.
- اعتماد ما يحتاجه المشروع فقط. لا تضف أقسامًا زائدة لمجرد الالتزام بقالب.
- تكون تعليمات التشغيل دقيقة ومتوافقة مع ملفات المشروع. لا تدرج أوامر قد تعيد تهيئة بيانات الإنتاج.
- روابط العرض والشعار وملفات الصور يجب أن تكون صحيحة.

## 2. ترتيب الأقسام

1. **Header:** شعار المشروع في المنتصف، الاسم العربي والإنجليزي، سطر تعريفي واحد أو اثنان، شارات التقنيات الأساسية، ورابط الموقع المنشور إن وجد.
2. **📱 Screenshots | صور المشروع:** صور فعلية لواجهات المشروع، بأبعاد مناسبة ووصف صغير. للمواقع يمكن وضع صورة سطح المكتب بعرض كبير وصورة الهاتف بعرض أصغر؛ للتطبيقات توضع 2–3 صور متجاورة عند توفرها.
3. **✨ Key Features | المميزات الرئيسية:** 5–8 نقاط تقريبًا، لكل نقطة اسم واضح وشرح قصير، دون سرد كل التفاصيل الصغيرة.
4. **🛠️ Tech Stack | التقنيات:** جدول بسيط يذكر التقنيات المستخدمة فعلًا وتصنيفها (Frontend / Backend / Database / Deployment)، ويُحذف أي صف غير مناسب.
5. **📂 Project Structure | هيكل المشروع:** شجرة قصيرة للمجلدات الأساسية فقط، مع تعليق بسيط يوضح وظيفة كل مجلد.
6. **🚀 Getting Started | التشغيل المحلي:** المتطلبات، الاستنساخ، إعداد البيئة عند الحاجة، تشغيل المشروع والبناء إن وجد.
7. **👨‍💻 Developer | المطور:** الاسم الشخصي، رقم التواصل، وحساب GitHub. لا تضف أسماء شركات أو روابط تجارية إلى بيانات المطور.
8. **License | الترخيص:** اختياري؛ يُذكر فقط إذا وُجد ترخيص معتمد فعلًا.

## 3. قواعد التنسيق البصري

- استخدم `<div align="center">` فقط لتوسيط الشعار والعنوان والشارات والرابط، أو تجميع صور الشاشة.
- يكون العنوان الرئيسي `#`، والأقسام `##`، والفواصل `---` بين الأقسام.
- للشارات استخدم `shields.io` بنمط `style=for-the-badge`، بعدد معقول، مع ألوان وشعارات التقنيات الصحيحة.
- الشعار بعرض مناسب (مثل `180`–`260` بكسل)، دون تكبير يطغى على الوصف.
- لا تُكثر الجداول: يكفي جدول التقنيات؛ المميزات قائمة نقطية سهلة القراءة.
- قدّم الصور بعد المقدمة مباشرة، ولا تستخدم صورًا تجريبية أو روابط مكسورة.
- تجنّب الزخارف الكثيرة، الخطوط الصغيرة، النصوص الطويلة، والتكرار.
- لا تكتب عبارات مثل: «تم تنظيف المستودع»، «آخر توثيق»، «حُذفت الفروع»، «تم دمج النسخ»، «آخر نسخة»، أو تقارير التحديثات والصيانة.
- لا تذكر مزايا غير منجزة، ولا تَعِد بتصدر نتائج البحث أو أداء غير مقاس.
